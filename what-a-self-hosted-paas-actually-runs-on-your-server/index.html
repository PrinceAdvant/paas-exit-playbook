What a self-hosted PaaS actually runs on your server

Installing a self-hosted platform takes one command, which hides how much is running afterwards. Knowing the parts helps with sizing, security and debugging.

Control plane

A web dashboard and API, usually backed by its own database (often Postgres or SQLite) and sometimes a Redis instance for queues. This is where projects, users and settings live. Back it up like any other database.

Reverse proxy

Traefik, Caddy or Nginx receives all HTTP and HTTPS traffic, terminates TLS and routes requests to containers by hostname. It also requests and renews certificates. If a site is down but its container is healthy, the proxy is the first place to look.

Builder

Something has to turn a Git repository into an image: Docker BuildKit, Nixpacks or buildpacks. Builds are the biggest CPU and memory spikes on a small server.

Agent or SSH connection

To manage remote servers, platforms either install an agent or connect over SSH. Know which, and which port and key it uses.

Your apps and databases

Ordinary containers and volumes, attached to Docker networks the platform creates.

Background jobs

Scheduled backups, certificate checks, cleanup of old images. These keep disk usage under control.

Security implications

The control plane has root-equivalent access to Docker. Protect its login with strong authentication, keep it updated and avoid exposing its port directly to the internet when a proxied domain is available.
