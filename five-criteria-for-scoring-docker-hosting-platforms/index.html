PaaS Exit Playbook

Five criteria for scoring Docker hosting platforms

Lists of Docker hosting platforms compare features that every option has. A scoring sheet with five weighted criteria makes the decision clearer for your situation.

1. Cost at your size

Estimate the monthly bill for your actual services: number of containers, memory each, a database, egress. Do this for today and for three times today. Usage-billed platforms and flat-priced servers diverge quickly as you grow.

2. Control

Can you pick the region, the base image, the network layout and the database version? Can you SSH in when something odd happens? More control means more responsibility, so weight this by how much your team wants.

3. Day-two operations

Logs, metrics, backups, rollbacks and alerts. Test each one on a trial account. A platform that deploys nicely but makes restores hard scores low here.

4. Scaling path

What happens when one service needs more resources? Vertical resize, more replicas, a second server? Know the next step and its price before you need it.

5. Exit cost

How hard is it to leave? If your apps are standard Docker images and Compose files, exit cost is low. Proprietary build systems, config formats and managed services raise it.

Weighting

A solo developer might weight cost and day-two operations highest. A regulated team might weight control and exit cost. Score each platform from one to five per criterion, multiply by the weight and compare totals.
