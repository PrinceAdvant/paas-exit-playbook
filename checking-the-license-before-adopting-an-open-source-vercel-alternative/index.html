Checking the license before adopting an open-source Vercel alternative

"Open source" covers several licenses with different obligations. For a deployment platform you run internally, most are fine, but it is worth reading before you build a business process on top of one.

Permissive: MIT and Apache 2.0

You can use, modify and run the software for any purpose, including commercially. Apache 2.0 adds an explicit patent grant. If you modify the platform, you do not have to publish your changes.

Copyleft: AGPL 3.0

You can use it freely. If you modify it and let users interact with it over a network, you must offer those users the modified source. For internal use by your own team, this rarely matters. If you plan to offer the platform as a service to customers, read it carefully.

Source available

Licenses such as the Business Source License or custom "fair code" licenses let you read and self-host the code but restrict certain uses, often competing hosted offerings. They are not open source by the OSI definition. Check whether your use is allowed and whether the license converts to an open source one after a set period.

Open core

The core is open source and some features, such as SSO or audit logs, are under a commercial license. Check which features you need fall on which side.

Practical checks

  • Read the LICENSE file in the repository, not the marketing page.
  • Check whether the license has changed in the past and how the project handled it.
  • Confirm that your apps remain ordinary containers if you ever need to switch.
