Next.js output standalone: what gets copied and what you must copy yourself

Setting output: "standalone" in next.config.js makes next build produce a self-contained server in .next/standalone. It traces the dependencies your server code imports and copies only those, which shrinks images dramatically. It does not copy everything.

What is included

  • server.js, a minimal Node server that runs your app.
  • A trimmed node_modules with only the traced packages.
  • The server side build output under .next/server.

What is missing

  • public/: static files are not copied. Copy public into .next/standalone/public.
  • .next/static: hashed client assets are not copied either. Copy them to .next/standalone/.next/static.

A minimal final stage looks like this:

FROM node:20-alpine
WORKDIR /app
ENV NODE_ENV=production
COPY --from=build /app/.next/standalone ./
COPY --from=build /app/public ./public
COPY --from=build /app/.next/static ./.next/static
EXPOSE 3000
CMD ["node", "server.js"]

Things that trip people up

  • Dynamic requires. Files loaded with a computed path may not be traced. Add them with outputFileTracingIncludes.
  • Host and port. server.js reads PORT and HOSTNAME. Set HOSTNAME=0.0.0.0 so it listens on all interfaces inside the container.
  • Monorepos. Set the tracing root to the repository root, or packages from other workspaces will be missing.
  • Image cache. .next/cache is not part of the standalone output. Mount a volume if you rely on image optimization.
